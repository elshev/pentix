# Agent skills

This page records which skills the repository carries, where each one came from, and what changed after the copy.

## Layout

A skill lives in four directories, one per supported agent. The four copies stay identical, apart from the Codex-only `agents/openai.yaml`.

```text
.cline/skills/<name>/       Cline
.codex/skills/<name>/       Codex, plus agents/openai.yaml
.opencode/skills/<name>/    OpenCode
.github/skills/<name>/      GitHub Copilot
```

`.clinerules/workflows/`, `.opencode/command/`, and `.github/prompts/` hold the slash-command wrappers. Only the four openspec skills have a wrapper today.

## Prose and the linter

The upstream body keeps the upstream prose. The linter therefore reports hard violations in each ported file, mostly sentences over the 20-word cap. The `## Pentix project notes` section passes the linter on its own.

When you change a ported skill, pass its baseline count, so only a new violation fails the check:

```bash
python .cline/skills/asd-ste100/scripts/ste-lint.py --baseline <n> .cline/skills/<name>/SKILL.md
```

## Update model

The repository vendors these skills. It does not install them through an upstream installer.

Decision date: 2026-11-27. The machine now runs Node `v26.13.1`, so `npx skills@latest` can run. The installer is still declined, for three reasons:

- It copies plain upstream files, so every `## Pentix project notes` section and every local body edit would be lost on the next update.
- Cline is not a target in its `-a` list, so `.cline/skills` would stay a manual copy.
- The plugin paths for Codex and Copilot install into the agent, not into this repository, so a checkout would no longer carry the pinned versions.

## Who runs the update, and when

The repository maintainer runs it, by hand, when a specific upstream change is wanted or when a ported skill misbehaves. It is not a scheduled job, not a CI step, and not part of a feature change.

The AI agent does not run it on its own. The agent may run the report mode when the user asks for it in that session, and it reads the report to the user. The agent runs `-Apply` only when the user asks for that write in that session.

Two gates enforce this:

- The script writes nothing without `-Apply`.
- `-Apply` asks the operator to type the skill name. An unattended run stops at that prompt.

Nothing in this repository calls the script. There is no workflow in `.github/`, and `package.json` has no `postinstall` or `prepare` hook.

## Update procedure

Use the helper script. It rebuilds one skill as upstream plus the local notes, shows the change, and mirrors the result.

```powershell
# Report only, nothing written
powershell -NoProfile -File scripts\update-agent-skill.ps1 -Name tdd

# Write and mirror
powershell -NoProfile -File scripts\update-agent-skill.ps1 -Name tdd -Apply
```

The script does these steps:

1. Read the upstream tree from the GitHub API.
2. Download every file of that skill into `$env:TEMP`.
3. Keep the local `## Pentix project notes` section.
4. Compare the rebuilt files with the local copies, in UTF-8.
5. With `-Apply`, write `.cline/skills/<name>/` and mirror it to the three other directories. The Codex copy keeps `agents/openai.yaml`.
6. Print the linter result, so you can refresh the baseline.

### Skills with body edits

Six ports change the upstream body as well as adding notes. An upstream change to one of these files needs a hand merge, and the script refuses `-Apply` until the body matches again:

| Skill | Body edit |
| --- | --- |
| `code-review` | The tracker paragraph names an openspec change |
| `domain-modeling` | The file structure block names `GLOSSARY.md` and `docs/decisions/README.md` |
| `improve-codebase-architecture` | Four lines name the decision index instead of ADR paths, and the skill invocations replace "Skill tool" |
| `tdd` | Two lines name the decision index and the skill invocation |
| `grill-me` | The description gains trigger phrases, and the body invokes the skill |
| `wait-what` | The description gains trigger phrases |

`-Force` writes upstream plus notes and drops those edits. Use it only to start a deliberate re-port of that skill.

The other seven ports differ from upstream only by the notes section, so `-Apply` works in one step.

## Not ported

These upstream skills stay out, because openspec already owns the workflow or the target environment is absent:

- `ask-matt`, `implement`, `implement-spec`, `to-spec`, `to-tickets`, `triage`, `wayfinder`, `setup-matt-pocock-skills`, `grill-with-docs`. OpenSpec already covers propose, apply, and archive, and this repository has no issue tracker.
- `handoff`, `research`, `retro`, `pr`. Useful later. Each one needs a target that this repository does not have yet.
- `wizard`. It generates bash wizards, and this repository is Windows-first.
- `misc/git-guardrails-claude-code`, `misc/migrate-to-shoehorn`, `misc/scaffold-exercises`, `misc/setup-pre-commit`. No Claude Code hooks, no `shoohorn` dependency, no Husky, no Prettier.
