## Why

The rewrite to replayable engine logs dropped the classic last-tick side-step: every built-in log ends with `H`, and the driver settles the piece on the same interval it hard-drops it, so a placement that only a one-column side-step can reach — the pocket under a mino on the row before last, for example — is still scored and chosen by the planner but never executed. The demo therefore steers to the right column and then locks beside the pocket instead of inside it. In parallel, the standalone authoring brief still describes the game only generically (it never lists the 29 catalog blocks, never explains the post-drop last tick, and still allows JavaScript), and the demo hot path pays for a full board-snapshot conversion and a grid clone per candidate on every spawn.

## What Changes

- Restore the last-tick move **after** the hard drop in the log contract: a `DemoActionLog` MAY carry exactly one action after `H`. The driver applies `H`, then that action, then the interval's gravity tick, all in the same interval, so the piece shifts one column on its last tick and locks there. A log that ends with `H` keeps today's behaviour.
- Make `delphi5` emit the last-tick move: the classic destination grows a `lastTickMove` field (`'L'`, `'R'`, or `null`) derived from the winning shifted candidate, and `actionsToward` accepts that optional code so an authored engine can express the same thing with one call.
- Keep `planDemoLastTickMove` as the pure classic helper for the session-based planner and its tests; the browser demo still plans once per piece and never re-plans mid-piece.
- Rewrite `docs/demo-engine-task.md`: add the **full list of the 29 catalog blocks** (key, id, mino count, rotation mode, colour, offsets, and a shape diagram with the rotation point marked), add a section that explains the last-tick move after `H` (with a worked pocket example and the exact driver rule), add the **scoring rules** that make the goal explicit (a lock, the hard drop with its "the earlier and higher the drop, the more points" rule, each cleared row, the emptied-board bonus, and the level multiplier), and make the brief TypeScript-only (TypeScript signatures required, every example in `ts`, no "plain JavaScript" wording).
- Update `docs/foundation.md` (and the root `README.md` where it summarises the demo) to describe the post-drop last tick and the TypeScript authoring contract.
- Optimize the demo planners: run the classic heuristic directly on the `0`/`1` board instead of converting it to a `BoardSnapshot`, score a candidate by writing its cells into one scratch grid and counting holes and full lines only in the touched columns and rows, and probe placements by walking offsets without allocating a cell array per probe.
- Refactor for one code path per concern: memoize `Piece.occupiedOffsets`, collapse the duplicated `demoStep`/`demoBoardStep` reducer branches into one board-addressed step, add a pure `nextDemoStep` helper that returns the action plus the last-tick action, and share the test harness that replays a log as Action-then-Tick.
- Seed every demo session: each demo session — the main attract demo on the page load, after a player game, and on every automatic restart, plus every rail demo board — starts with one settled mino on the row before last in a random column, which stays on the board until its row is cleared, so the demo always has an overhang to plan around. Player sessions start empty.
- Keep the demo engine the player chose: the main board's demo engine now survives a player session, a restart, and the demo that follows, so a demo engine a double-click brought to the main board stays there until the page is reloaded. Only the rail is reassigned in registry order.
- Make the build deterministic: `build:core` and `build:server` remove their `dist` directory first, so renamed or deleted modules no longer linger as stale compiled output (`demo-delphi5.js`, `demo-engines/random.js`, `demo-engines/left-wall.js` exist today).

### Modified Capabilities

- `demo-engines`: the action log may carry one action after `H` as the last-tick move, `actionsToward` accepts it, and `delphi5` plans it so the classic side-step placements are actually executed; the destination type reports the last-tick direction.
- `demo-mode`: every demo session starts with one seeded mino on the row before last; the demo applies a hard drop, the log's following action, and the interval's tick as one step, discards that follow-up action when the drop settles the piece, never applies an unplanned extra tick, and keeps the selected demo engine across player sessions.
- `demo-boards`: a rail board replays the same post-drop last tick with its own engine, starts with its own seeded mino, a step whose drop settled the piece leaves the next piece untouched, and a later board set keeps the main board's engine while the rail returns to registry order.
- `repository-documentation`: the authoring brief must list every catalog block, must state the post-drop last-tick rule, and must require a TypeScript answer; the foundation notes must describe the same rules.

## Impact

- Affected code: `packages/pentix-core/src/demo.ts` (destination carries the last-tick move; heuristic on the `0`/`1` board; local scoring; no-allocation probes), `demo-actions.ts` (`actionsToward` last-tick argument, allocation-free `demoCanPlace`), `demo-engine-toolkit.ts` (re-exports), `demo-engines/delphi5-demo-engine.ts` (emits the side-step, drops the snapshot conversion), `piece.ts` (memoized `occupiedOffsets`), `apps/pentix-web/src/engine/demo.ts` (pure `nextDemoStep`), `apps/pentix-web/src/engine/gameReducer.ts` (one board-addressed demo step, follow-up action handling, seeded demo sessions, inherited main demo engine), `apps/pentix-web/src/games/pentix/useDemoController.ts` (one dispatch path), `tests/pentix-core.test.mjs` and `tests/pentix-web.test.mjs` (side-step, settled-drop guard, seeded demo starts, engine persistence, shared replay helper), `package.json` (`dist` clean before compile), `docs/demo-engine-task.md`, `docs/foundation.md`, `README.md`.
- Affected APIs: additive core exports (`DemoDestination.lastTickMove`, `DemoOrientationDestination.lastTickMove`, `actionsToward(orientation, position, column, lastTickMove?)`); the `DemoActionLog` grammar gains one post-`H` action; the web `GameAction` union replaces `demoStep`/`demoBoardStep` with one `demoStep` carrying `boardId`. No HTTP, server, storage, or session-replay format changes, and no new runtime dependency.
- Behavioural impact: `delphi5` (and any engine that opts in) now takes its last-tick side-step, so demo pieces land in pockets they previously missed and demo statistics and cleared-line counts shift slightly; `random` keeps ending its logs with `H`, so its boards behave as today. Every demo board now opens with one settled mino on the row before last, which the demo plays around until that row clears, while player games still start empty. The main board keeps the demo engine the player swapped in, across games and restarts. Planning is faster because the per-candidate grid clone and the per-cell board conversion are gone.
- Affected teams/areas: owners of the shared demo planners and the demo-engine toolkit in `pentix-core`, the demo-engine authors (human or AI) who follow `docs/demo-engine-task.md`, and the `pentix-web` client that drives the main board and the rail. The server, storage, and replay paths are untouched.
- Dependencies: none — no new packages; the `dist` clean uses Node's built-in `fs` module.
- Rollback plan: revert `actionsToward` and the destination type to the pre-change shape, drop the post-`H` handling from the web step (the driver then settles on the drop interval again) and restore the two demo-step actions, restore the previous `docs/demo-engine-task.md` and `docs/foundation.md` text, and drop the `dist` clean from `package.json`. `planDemoLastTickMove` and `planDemoDestination` stay in both directions, so the classic planners survive a partial rollback and no server or storage state depends on this change.
